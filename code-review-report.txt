1. 项目概览
================================================================================

search_deb（kylinpkgtool）是一个基于 PyQt5 的银河麒麟 V10 桌面图形化工具，核心
功能包括：按目标架构与产线版本切换软件源、查询可用版本并下载 .deb 软件包、按
文件名/库名反查所属软件包。项目结构清晰，职责分层合理：

  - src/apt_core.py        核心模块：apt 命令构建与结果解析（纯逻辑，无 GUI 依赖）
  - src/runner.py          异步命令执行（QThread），避免阻塞 GUI
  - src/main_window.py     主窗口 GUI（PyQt5），约 710 行
  - src/data_models.py     软件源数据（由 Excel 生成），约 775 行
  - src/utils.py           通用工具（桌面路径获取）
  - tools/                 辅助工具（Excel 转数据模型、图标生成）
  - packaging/             deb 打包配置

整体评价：项目代码质量整体良好。命名规范清晰，shlex.quote 被系统性地用于所有
用户输入的 shell 引用，有效防止了命令注入。备份/恢复机制设计完善，首次操作前
自动备份原文件。以下是审查中发现的具体问题。

2. 严重 Bug 分析

--------------------------------------------------------------------------------
[严重] Bug #1: parse_dependencies 可能遗漏带版本约束的依赖包
--------------------------------------------------------------------------------
文件: src/apt_core.py · 第 268 行

问题描述:
  在解析 apt-cache depends 输出时，代码使用 " " in line 来过滤非包名行。但若
  依赖行包含版本约束（如 libssl1.1 (>= 1.1.0)），版本约束中的空格会导致整个
  依赖被错误跳过，使"下载依赖项"功能产生不完整的依赖列表。

  当前代码（第 266-269 行）:
    line = line.split(" | ", 1)[0].strip()
    if line.startswith("<") or " " in line:      # <-- 问题在此
        continue
    # 含版本约束的依赖 "libssl1.1 (>= 1.1.0)" 会因含空格被跳过

  虽然 apt-cache depends 默认不显示版本约束，但在某些麒麟定制版本或特定 apt
  配置下可能输出带约束的依赖，此检查存在脆弱性。

修复建议:
  在空格检查之前，先剥离版本约束部分：

    line = line.split(" | ", 1)[0].strip()
    line = line.split("(", 1)[0].strip()  # 移除版本约束
    if line.startswith("<") or " " in line:
        continue

[严重] Bug #2: data_models 中 Pin 配置等号后多余空格导致优先级失效
--------------------------------------------------------------------------------
文件: src/data_models.py · 第 661 行 · "wayland 华为flemingx" 版本

问题描述:
  该版本的 Pin: release 行中 a= 后存在一个空格：
    'Pin: release a= 10.1-2403-wayland-update2-kirin9000C-pre-bugfix-limit'

  apt preferences 解析时，等号后的空格会导致 release 匹配失败，使该版本的两
  个 Pin 规则（priority 600）完全失效，可能导致包安装时选择了错误版本的软件包。

  data_models.py 第 660-662 行:
    'Pin: release a= 10.1-2403-wayland-update2-kirin9000C-pre-bugfix-limit',  # <-- 问题
    'Pin-Priority: 600',

修复建议:
  移除 a= 后的空格，改为 a=10.1-2403-wayland-update2-kirin9000C-pre-bugfix-limit。
  同时建议在 excel_to_data_models.py 的 _extract_lines 函数中增加自动规整：
    line = re.sub(r'(a=)\s+', r'\1', line)
  防止 Excel 数据再次引入此问题。

[严重] Bug #3: closeEvent 线程等待超时不足，可能引发 QThread 销毁崩溃
--------------------------------------------------------------------------------
文件: src/main_window.py · 第 706-709 行

问题描述:
  关闭窗口时，worker.wait(3000) 仅等待 3 秒。当 pkexec 授权窗口弹出但用户未
  及时响应时，3 秒不足以等待用户完成密码输入。超时后窗口关闭但线程仍在运行，
  Qt 会在 QThread 仍在运行时被销毁，触发 "QThread: Destroyed while thread is
  still running" 崩溃。

  当前代码:
    def closeEvent(self, event):
        worker = self._worker
        if worker is not None and worker.isRunning():
            self.log("正在停止后台任务...")
            worker.stop()
            worker.wait(3000)  # 仅 3 秒
        event.accept()

修复建议:
  增加等待时间至 10 秒，并在超时时强制中断；或改为在 worker 的 finished 信号
  中才真正关闭窗口：

    def closeEvent(self, event):
        worker = self._worker
        if worker is not None and worker.isRunning():
            self.log("正在停止后台任务...")
            worker.stop()
            if not worker.wait(10000):
                self.log("强制终止超时任务")
                worker.terminate()
        event.accept()

3. 中等问题
================================================================================

--------------------------------------------------------------------------------
[中等] Bug #4: 部分软件源使用 HTTP 明文传输
--------------------------------------------------------------------------------
文件: src/data_models.py · XC / HWE / 部分 wayland 版本

问题描述:
  XC 和 HWE 产品线的所有版本以及部分 wayland 版本使用
  http://archive.kylinos.cn/... 而非 HTTPS。虽然 apt 有 GPG 签名验证，但明文
  传输仍存在中间人攻击风险，攻击者可观察用户下载的包名和版本信息。

修复建议:
  将所有 http://archive.kylinos.cn 和 http://archive2.kylinos.cn 统一替换为
  https://。服务器已支持 HTTPS（wayland 版本已在使用），可安全切换。

--------------------------------------------------------------------------------
[中等] Bug #5: clear_all 按钮在任务执行期间未禁用
--------------------------------------------------------------------------------
文件: src/main_window.py · 第 129-130 行 / 第 243-248 行

问题描述:
  "清空"按钮 (btn_clear) 不在 _action_buttons 列表中，set_busy(True) 时不会被
  禁用。用户可以在下载或搜索过程中点击"清空"，导致日志和搜索结果在任务运行中
  被意外清除，而后续的回调仍会向已清空的日志框写入。

修复建议:
  将 btn_clear 加入 set_busy 的禁用列表，或在 clear_all 开头增加
  if self._busy: return 保护。

--------------------------------------------------------------------------------
[中等] Bug #6: combined_privileged_cmd 结果标记可被命令输出伪造
--------------------------------------------------------------------------------
文件: src/apt_core.py · 第 157-158 行

问题描述:
  合并授权命令通过 printf '\nKYLINPKGTOOL_RESULTS:%s\n' 输出结果标记，
  main_window.py 用 startswith(marker) 从输出末尾查找。虽然正常 apt 命令不会
  输出此前缀，但若被操作的源文件或 apt 输出中包含此字符串，可能被误识别为结果
  标记，导致解析出错误的状态码。

修复建议:
  使用更难碰撞的标记，如 __KYLINPKGTOOL_RESULTS_V2__，或改用文件描述符/临时
  文件传递结果码，避免与命令输出混在同一 stdout 流中。

--------------------------------------------------------------------------------
[中等] Bug #7: dependencies_download_cmd 中 Architecture 检测的竞态条件
--------------------------------------------------------------------------------
文件: src/apt_core.py · 第 199-206 行

问题描述:
  依赖下载逻辑通过 apt-cache show "$pkg:$arch" | grep -Fxq "Architecture: $arch"
  判断包是否有目标架构候选。但 apt-cache show 可能输出多个版本 stanza，grep
  只要有任一版本匹配即通过，而 apt download 可能下载到非目标架构的版本。此外
  grep -Fxq 'Architecture: all' 的回退路径中，apt-cache show 的输出格式在不同
  apt 版本间可能有细微差异。

修复建议:
  改用 apt-cache policy "$pkg:$arch" 检查是否有候选版本（Candidate 不为
  (none)），这比 grep 匹配更可靠。或直接尝试 apt download "$pkg:$arch"，失败后
  回退到 apt download "$pkg"，由 apt 自身处理架构选择。

[低] Bug #8: Pin-Priority 格式不一致
--------------------------------------------------------------------------------
文件: src/data_models.py · 多处

问题描述:
  部分条目使用 "Pin-Priority: 600"（冒号后有空格），部分使用
  "Pin-Priority:600"（无空格）。apt 两种格式均接受，但不一致的数据不利于维护

--------------------------------------------------------------------------------
[低] Bug #9: deb 行中存在多余空格
--------------------------------------------------------------------------------
文件: src/data_models.py · 第 299、331、570 行等

问题描述:
  多处 deb 行有双空格，如 "KYLIN-ALL  10.1-2303-wayland-bugfix-limit  main"。
  apt 对多余空格有容错，但不规范的格式可能导致 apt 在某些严格解析模式下报告
  warning。

修复建议:
  在数据生成脚本中添加 re.sub(r' {2,}', ' ', line).strip() 规整。

--------------------------------------------------------------------------------
[低] Bug #10: 缺少包名输入验证
--------------------------------------------------------------------------------
文件: src/main_window.py · 第 443 行 / 第 480 行

问题描述:
  用户在 pkg_edit 中输入的包名未做格式校验即传入 apt 命令。shlex.quote 防止了
  注入，但非法包名会导致 apt 返回难以理解的错误信息。

修复建议:
  在调用前用 _PKG_NAME_RE 正则校验，给出友好的提示。

--------------------------------------------------------------------------------
[低] Bug #11: parse_versions 正则可能遗漏字母开头的版本号
--------------------------------------------------------------------------------
文件: src/apt_core.py · 第 231 行

问题描述:
  正则 r"^(\d[\w.\-:+~]+)\s+\d+" 要求版本号以数字开头。Debian 版本号通常以
  数字开头，但极少数以字母开头的版本号会被遗漏。

修复建议:
  放宽为首字符为字母或数字：
    r"^([a-zA-Z0-9][\w.\-:+~]+)\s+\d+"

--------------------------------------------------------------------------------
[低] Bug #12: excel_to_data_models.py 重复检测使用 O(n²) 算法
--------------------------------------------------------------------------------
文件: tools/excel_to_data_models.py · 第 167-170 行

问题描述:
  names.count(name) 在列表推导中对每个元素调用一次，时间复杂度为 O(n²)。
  当前约 40 个条目影响不大，但建议改进。

修复建议:
  用 collections.Counter 替换，降为 O(n)。

[低] Bug #13: use_selected_package 缺少 busy 状态检查
--------------------------------------------------------------------------------
文件: src/main_window.py · 第 692-700 行

问题描述:
  use_selected_package 方法未检查 self._busy。虽然按钮在忙碌时被禁用（通过
  set_busy），但如果通过其他途径（如快捷键）触发，可能在任务运行中启动新的
  查询命令。

修复建议:
  在方法开头加 if self._busy: return。

5. 安全考量
================================================================================

整体安全评估：良好。项目在命令构建层面做了系统性的安全防护，以下是详细分析。

5.1 命令注入防护 — 合格
  所有用户输入（包名、版本号、搜索关键词、架构名）在传入 shell 命令前均经过
  shlex.quote() 处理。命令构建集中在 apt_core.py 中，未在 GUI 层直接拼接 shell
  命令。runner.py 虽使用 shell=True，但由于命令字符串已预先完成引用，注入风险
  被有效消除。

5.2 提权操作 — 合格
  需要 root 权限的操作通过 pkexec 执行，未使用不安全的 sudo 管道方式。
  combined_privileged_cmd 将多条管理员命令封装进同一 shell 会话，减少用户密码
  输入次数。每条命令的返回码通过独立标记传递，可逐条检查成功与否。

5.3 文件操作 — 合格
  源文件和优先级文件的写入采用"备份→临时文件→原子替换"模式（mktemp + mv -f），
  避免了写入中途断电导致的文件损坏。恢复操作有完整的状态记录（.saved /
  .original / .absent），不会误删系统原有配置。

5.4 需关注的安全改进点

  - HTTP 明文源：XC/HWE 版本使用 HTTP，建议全面切换为 HTTPS（详见中等问题 #4）。

  - pkexec 授权范围：combined_privileged_cmd 中 set +e 使所有命令都会执行，
    即使前序失败。这虽然便于逐条报告状态，但也意味着在源写入失败时仍会继续执行
    apt update，可能基于残留的旧源刷新索引。建议在关键步骤（如 source 写入）
    失败后跳过后续依赖步骤。

  - 进程组终止：stop() 使用 SIGKILL 终止整个进程组，这是最激进的方式。
    apt download 的子进程可能正在写入 .deb 文件，SIGKILL 不允许清理，可能留下
    不完整的下载文件。建议先尝试 SIGTERM，短超时后再 SIGKILL。

6. 优化建议
================================================================================

1) 添加单元测试覆盖核心解析函数
   apt_core.py 中的 parse_versions、parse_dependencies、parse_search_packages、
   extract_search_terms 都是纯函数，非常适合单元测试。建议添加
   tests/test_apt_core.py，使用真实的 apt 输出样本作为测试数据，防止解析逻辑
   回归。这是收益最高的改进——上述 Bug #1 就能被测试直接发现。

2) 增加输入验证层
   在 main_window.py 中为包名、版本号添加格式验证。利用
   apt_core.AptManager._PKG_NAME_RE 校验包名，利用版本号正则校验版本。验证
   失败时给出友好的中文提示，而非让 apt 返回晦涩的错误。同时在 data_models.py
   中增加 validate_entries() 函数，在模块加载时自动校验 deb 行格式和 Pin 语法。

3) 拆分 main_window.py
   当前 main_window.py 约 710 行，包含了 UI 构建、下拉联动、异步执行封装、6 大
   功能模块的回调逻辑。建议按职责拆分：ui_builder.py（UI 构建）、
   command_controller.py（命令编排与回调）。或至少将搜索相关的逻辑
   （search_files 到 _on_fallback_done）提取为独立的 SearchController 类。

4) 数据源外置为 JSON/YAML 配置文件
   当前 data_models.py 是从 Excel 生成的 775 行硬编码 Python 文件。虽然生成
   流程清晰，但数据与代码耦合在同一个 .py 文件中。建议将 VERSION_ENTRIES 外置
   为 sources.json，data_models.py 仅负责加载和查询逻辑。这使数据更新无需重新
   生成 Python 文件，也便于 diff 审查数据变更。

5) 添加类型注解
   项目完全没有类型注解。为 apt_core.py 和 data_models.py 的函数添加类型提示
   （如 def parse_versions(output: str) -> list[str]:），可以显著提高 IDE 辅助
   能力和代码可维护性。可配合 mypy 做静态类型检查。

6) 改进下载终止策略
   将 runner.py 的 stop() 方法改为"先礼后兵"：先发送 SIGTERM（允许 apt 清理
   临时文件），等待 2 秒后若进程仍存活再 SIGKILL。这能避免下载中断时留下不完整
   的 .deb 文件，也避免 apt 的锁文件未被释放。

7) 日志持久化
   当前运行日志仅显示在 GUI 的 QPlainTextEdit 中，关闭窗口即丢失。建议将日志
   同时写入 ~/.local/share/kylinpkgtool/kylinpkgtool.log，便于用户在遇到问题时
   提供调试信息。可用 Python logging 模块配合 FileHandler 实现。

8) 下载进度反馈
   当前下载仅显示 apt 的文本输出，缺乏直观的进度指示。可以在下载期间在状态栏
   或按钮旁显示 QProgressBar，解析 apt download 的输出（如 "Get:1 ... 100%
   [...]"）提取进度百分比，提升用户体验。

9) 在 excel_to_data_models.py 中增加数据校验
   在 parse_entries 的末尾增加对生成数据的格式校验：deb 行是否以 "deb " 开头
   且包含 URL 和 suite；Pin 行的 a= 后无空格；Pin-Priority 后为有效数字。这能
   在数据生成阶段就捕获本文报告中发现的数据类 Bug。

10) 添加 GitHub Actions CI
    配置 GitHub Actions 工作流，在每次 push/PR 时自动运行：
    python -m py_compile src/*.py（语法检查）、python -m pytest tests/（单元
    测试）、python -m flake8 src/（代码风格检查）。CI 能在合并前自动拦截语法
    错误和回归。
